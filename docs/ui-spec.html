01先诊断：三个实测问题

改颜色、换圆角之前，这三条才是观感的决定性因素。

字体根本没加载 —— 标题实际渲染成「宋体」已完成

main.css 声明了 --serif: "Noto Serif SC", "Songti SC", "STSong", "SimSun"， 但全项目没有任何字体加载代码（0 个 @font-face、0 个 Google Fonts 引用、无 fontsource 依赖）。 本机没装 Noto Serif SC，于是回退到 SimSun（宋体）——屏幕上最老气的字体，也正是「像 Word 学术报告」的头号原因。

→ 已解决：标题改用无衬线，--serif 直接指向 --font-sans。 同时决定不加载任何 web font——Google Fonts 在国内不稳，而系统中文字体本身就够用。

图标体系是混的 —— 16 个内联 SVG + 17 种 emoji部分完成

🟢🟡🔴 表示证据充分度、👨‍⚕️ 表示行动建议、💬 表示追问、⚠️ 表示提醒…… Emoji 在不同系统渲染差异极大（Windows 是扁平彩色、macOS 是拟物）， 而且彩色圆点在严肃医学语境下显得随意，同一屏里 SVG 线性图标和彩色 emoji 混排也不统一。

→ 已删掉标题里的 emoji（👨‍⚕️ 专家行动建议、💬 您可能还想问、⚠️ 提醒）， 改用文字层级本身表达结构。但Lucide 未引入：手写 SVG 仍在 17 处， 且 stroke-width 混用 1.4 / 2 / 2.2 / 2.4——这一项仍是待办。

设计变量没有纪律 —— #a0522d 和 --clay 是两个不同的棕色已完成

实测：42 种硬编码色值出现 150 次（其中 #a0522d 用了 26 次， 而 token 里定义的主色是 --clay: #B85A36）。 另有 23 种字号、11 种圆角。 结果是「说不出的不统一」——每个局部看着都对，整页却没有整体感。

→ 已解决：色值全部并入 token（42 种 → 3 种例外）、字号收敛到 8 档、圆角降到 5 档， 并补上了若干「被引用但从未定义」的 token（如 --line-2）。

02可借鉴的开源项目

按「改造成本从低到高」排序。你的技术栈是 Vue3 + Element Plus，所以优先列同生态的。 许可证都确认过——这几个都是宽松许可，可安全借鉴。

最终结论：一个依赖都没引入，只借了模式。 shadcn-vue 与 Nuxt UI 都要带进 Tailwind（Nuxt UI 还要 Reka UI），会和现有的 Element Plus + 手写 CSS 打架——Tailwind 的 preflight 重置尤其容易冲突，对当前规模收益远小于风险。 实际拿走的是：token 纪律（shadcn-vue 的语义成对、border 分层、圆角克制）、 按钮权重分级与「一屏只允许一个实心主按钮」（Nuxt UI 的设计指南）、 长文排版里「阅读宽度上限」的思路（Tailwind Typography）。
shadcn-vueMITgithub.com/unovue/shadcn-vue

不是组件库，是「把组件源码复制进你项目」的模式。你可以只拿 Card / Tabs / Dialog / Badge 几个， 按它的样式改，不需要整体迁移，也不需要动 Element Plus。 它的审美正是 Linear / Notion 那一挂——「知识社区」而不是「医疗软件」，和你的目标一致。

Nuxt UIMITgithub.com/nuxt/ui

Vue 生态里「内容型产品」排版做得最舒服的一套。它的 landing 区和文档页排版可以直接借鉴你的首页与长文回答区。 是 Nuxt 模块，但组件底层基于 Reka UI，样式思路可移植。

@tailwindcss/typographyMITgithub.com/tailwindlabs/tailwindcss-typography

单点杠杆最高的一个。它那套 prose 规则专门解决「长文怎么排才读得下去」—— 正是你 AI 回答区块的痛点。即使不引 Tailwind，把它的 CSS 规则直接抄过来也完全可行。

LucideISCgithub.com/lucide-icons/lucide

一套线性图标，Vue 包现在叫 @lucide/vue（早期名 lucide-vue-next 已弃用）。 风格克制统一，能一次性替掉现在混用的手写 SVG 和 emoji。ISC 许可比 MIT 还宽松。 图标规范：24×24 网格、stroke-width="2"、stroke="currentColor"。 仍是待办——见 01 的第二条。

Arco Design VueMITgithub.com/arco-design/arco-design-vue

字节出品。如果你哪天想彻底换掉 Element Plus，这是最低痛苦的选项（同样 Vue3 + TS，中文文档齐全）。 它的默认观感比 Element Plus 现代——Element Plus 的默认蓝 + 直角是「后台味」的主要来源。

反面参考：vbenjs/vue-vben-admin（MIT）。它是国内最流行的 Vue3 Admin 模板， 但它的审美正是你想避免的——深色侧栏 + 密集表格。值得看的是它的工程组织（主题切换、明暗模式、token 管理），不是它的视觉。

03视觉规范

字体

这是投入产出比最高的一项。同一个标题，两种字体：

✗ 现在实际渲染（宋体）
白族糖尿病患病率是多少？
✓ 改用无衬线
白族糖尿病患病率是多少？

决定：标题也改用无衬线，靠字重和字号做层级——Notion、Linear、知乎都是这么做的。 宋体在屏幕上（尤其小字号）天然显旧，这是「学术报告感」的主要来源。 已完成

同时决定不加载任何 web font：Google Fonts 在国内访问不稳， 而"PingFang SC / 微软雅黑 / Noto Sans SC"这套系统中文字体栈本身已经够用。 --serif 作为历史样式里大量使用的兼容名保留，但值已指向 --font-sans。

语义色（成功/警告/危险）建议再降一点饱和度。医疗场景不适合高饱和的红绿—— 现在的 #B2473A 已经是偏砖红的好选择，保持即可。

阴影：更淡、更散

你现在的阴影偏硬（扩散小、透明度高）。知识类产品建议阴影更淡、靠边框和留白分层。 同一张卡片，三种深度：

sh-sm · 静态卡片
sh-md · hover 浮起
sh-lg · 弹窗 / 浮层

关键差异：扩散半径大、透明度低（如 0 4px 16px -6px rgba(70,50,30,.10)）， 看起来像「微微离开纸面」，而不是「贴了一张灰纸」。

间距：加一套 4px 基数

现在没有间距 token，padding/margin 全是手写的。建议加一套——这是让「留白合理」变得可执行的前提：

token值典型用途
--sp-14px图标与文字之间
--sp-28px标签之间、按钮内边距
--sp-312px卡片内元素间距
--sp-416px卡片内边距
--sp-520px卡片之间
--sp-624px区块内边距
--sp-832px区块之间

按钮分级：约 40 个类名 → 5 档权重 已完成

这一项不在原方案里，是执行过程中发现的最大一处重复：全站约 40 个各不相同的按钮类名、 60 处胶囊圆角；「危险」态重复实现过 4 遍（.mini.danger / .act.danger / .icon-btn.danger / 各处的 :disabled），hover 行为也各不相同 （有的填成实心、有的只换边框色、有的还上浮 1px）。

参考 Nuxt UI 的 variant 体系，按视觉权重收敛成五档，全部定义在 main.css 的 .btn 下，视图只写布局、不再各自定义按钮：

档位用途典型
.btn-solid主操作，一屏只允许一个开始对话 / 发送 / 解析
.btn-outline次要操作，以及并列的多个动作追问胶囊 / 列表行操作
.btn-soft标签式按钮、已选中的开关新建对话 / 已收藏
.btn-ghost图标按钮、行内动作重命名 / 关闭
.btn-link正文里的文字链接空状态里的跳转

配尺寸（btn-sm / btn-lg / btn-icon / btn-block / btn-rect）、 语义色（btn-danger / btn-sage）与选中态（is-on）。 效果是每个视图只剩一个实心主按钮——此前智能对话页同屏有三个实心陶土红 （新建对话 / 发送 / 分享至动态）互相抢注意力，现在只有「发送」保持实心。

空状态：4 套 → 1 套 已完成

同样是执行中补的。此前四处各写各的：动态页是「圆形插画 + 标题 + 说明 + 按钮」（最完整的一套）， 个人中心和对话列表是光秃秃一行灰字，书架是一段虚线框文字。

现在统一成 .empty-state 四段结构（插画 → 标题 → 说明 → 行动，缺哪段就不渲染哪段）， 配三档尺寸：默认（卡片内）/ -sm（行内、侧栏）/ -lg（整页）。 效果是每个空状态都能给出下一步，而不是「暂无数据」式的死胡同。

04逐页改造：方案与结果

下表的「改造前 / 当时建议」是动手前记下的，保留原样以便对照； 每页标题旁的标记与下方说明才是实际结果。

首页 方向调整

实际做法与建议不同。建议的「问答预览式 Hero」「三种用法」没有采纳——改为保留大标题（字号收小一档、 上下留白加大）作为主视觉，下方新增热门问题模块：8 条真实高频问题平铺成卡片，点一下直达回答。 理由是「别人在问什么」比「我们能做什么」更容易让人迈出第一步。 两页之间靠 /chat?q=<问题> 打通，未登录时随 redirect 带到登录后再执行。

现在是「居中大标题 + 开始对话按钮 + 5 个价值点胶囊」——像产品发布会落地页。 但用户（尤其少数民族群众）是带着具体健康疑问来的，抽象的价值主张对他没有意义。

改造前当时建议
抽象标题 + 自夸式能力标签用一段真实问答预览当主视觉——问题 + 通俗回答 + 一行依据来源。先给内容，再讲功能
「问得准 / 找得到 / 说得清 / 有依据 / 知边界」改成用户视角的三种用法：「我想知道我们民族的常见病」「帮我看懂一份研究」「这些数据可靠吗」
主按钮「开始对话」文案更具体：「问一个健康问题」
无信任锚加一行来源说明：「已收录 N 篇已审核文献」——比「证据溯源」这种词有实感

智能对话页 部分完成

已做：依据文献默认收起成一个 chip；输入框圆角加大 + 聚焦光晕； 区块标题改成「小字号 + 主色 + 左侧短竖线」，层级交给颜色建立而不是字号堆叠。
未做：追问胶囊仍在卡片内；左侧会话列表未加当前项色条。
另有几处不在方案内、但更影响体验的改动： 并发单飞锁（一次只允许一个问题在跑）、乐观更新（点下发送就清空输入框并挂出提问气泡）、 历史回放与实时回合合并成一条线程。这三项解决的是答案串号、内容丢失、页面卡死， 比视觉调整重要得多——详见 docs/architecture.html 第 07 节。

核心问题：一张回答卡片信息密度过高——核心解答 + 文献说明 + 行动建议 + 提醒 + 依据文献 + 追问胶囊 + 三个操作按钮，一屏装不下，读起来累。

改造前当时建议
所有模块视觉权重相同拉开主次：「专家核心解答」用 17px + 更多上下留白；其余模块 14px 浅色，让「先看结论」成为默认路径
依据文献直接展示引用框默认收起成一个 chip（「依据《数据资料》4 条」），点开才展开——溯源可信但不压场
追问胶囊在卡片内移到卡片外、下方留白处，视觉上「邀请继续问」而不是卡片的一个区块
左侧列表纯文字当前会话加左侧色条；分组标题（今天/昨天）加字重，与条目标题拉开层级
输入框普通直角圆角加大（--r-lg），聚焦时一圈柔和光晕（box-shadow: 0 0 0 3px var(--clay-soft)）

动态页 部分完成

已做：卡片间距 18px → 20px；卡片圆角收到 14px（对齐 shadcn 的 rounded-xl）； 作者名与操作按钮改为常驻显示，作者名可点进个人主页。
与方案相反的一处，需要说明：方案建议「列表行按钮改为 hover 才显形」， 实际改成了常驻。hover 门控会让触摸屏用户和不用鼠标的人根本发现不了「收藏」， 而那是这一页最核心的操作——可发现性优先于「静态好扫读」。个人中心的列表行同理。

双列瀑布流 + 极简标题卡片，这个方向已经对了。只需微调呼吸感：

改造前当时建议
卡片间距 18px20px，留白更透气
标题 15.5px / 行高 1.516px / 行高 1.6
每张卡都有绿色标签块标签底色再淡一档，避免整页泛绿、视觉疲劳

个人中心 部分完成

已做：统计数字放大到 21px 并加字距，做出轻量仪表盘感；两张卡片的圆角与内边距统一； 「我的对话」行的三个动作按钮改用统一的分级样式。
未做：列表行按钮改 hover 显形——理由同上，可发现性优先。
新增：访客模式（?userId=<id>）——可查看他人的公开分享， 对话与收藏属私有数据不对外；有独立的一套只读资料区。
改造前当时建议
统计数字与正文同字体数字用 22px + 字距微开，做成轻量「仪表盘」感
列表行三个按钮常驻改为 hover 才显形（与动态页卡片一致），列表更静态、更好扫读

后台工作台 已完成

这一页本来就该「像后台」——它是给管理员看的溯源工具，信息密度是优点不是缺点。 不要为了统一审美牺牲它。只需统一色板和字体即可。
